SAM: how it works today, and where it is going

SAM is Accops' sales and marketing "brain". A rep asks a question in plain words ("a banking case study I can send a CIO") and SAM points to the right document in the Sales Collateral library, says whether it can go to a customer, and links to it. This document explains how that works today and what we plan next. It replaces the older system map (docs/sam-how-it-works.html, 24 Sep 2026).

RAG

"Retrieval-augmented generation": first find the relevant material, then let an AI model write the answer from that material only.

Card

A one-page structured summary of one document (title, type, industry, product, year, visibility). Claude writes one card per document.

Passage

A short chunk of a document's own text, one page or slide at a time, used when a tool needs to quote what the document says.

Embedding

A list of numbers that captures a text's meaning, used for "search by meaning". SAM does not use embeddings today; it searches by words.

SAM end to end. Each numbered stage has its own section below.

Part 1

How SAM works today

As of 26 October 2026. Every claim is taken from the code and the project documents; sources are listed in small print under each section.

01Where the documents come from

SAM reads one library: Sales Collateral in SharePoint. SAM never writes to SharePoint and never changes a file. It keeps two views of the library: a list of files (kept current by Power Automate) and a full synced copy on Siddharth's laptop, which the nightly reading job uses.

Two paths out of one library. The file list arrives within minutes; the reading happens once a night.

Sources: docs/TASK-sharepoint-ingestion.md §4; docs/ROADMAP.md P5 ("Marketing 2.0 ... excluded until specific folders are named"); prototype/carding_prep.py (OneDrive path, "Why OneDrive"); registry count read 26 Oct 2026.

02Noticing changes

Two Power Automate flows keep the registry honest. One catches every add or edit within minutes. The other runs every night at 02:00 IST, lists the whole library, and marks files that have disappeared as deleted. It has a safety guard: if it can see fewer than 90% of the files SAM already knows about, it assumes the listing is broken and refuses to change anything.

The registry knows where every file is. It does not yet know what a new file says; that is the next step (carding).

The guard earned its keep in October. From 1 Oct, Power Automate's standard "Get files" step silently returned 283 fewer files (the oldest ones, created 2021-22) while still reporting success. Without the guard, SAM would have marked them all deleted. Instead it refused every night until Power Automate suspended the flow. On 19 Oct the listing step was replaced with direct paged listing; the first run listed 878, matched 878, deleted 0.

Sources: web/lib/sharepoint.ts (MIN_SHARE = 0.9, diffSnapshot); docs/TASK-snapshot-flow.md; docs/SALES-BRAIN-PLATFORM.md §3 Freshness; sam_ops_runs.

03Carding: reading each document once

A card is SAM's structured summary of one document. Cards are what SAM's answer model reads; it never reads the files themselves. Claude writes the cards every morning at 07:00 IST on Siddharth's laptop, for any file that is new, changed or renamed since its last card. The cards are saved to git (so every card can be reviewed and rebuilt) and loaded into the database.

The nightly carding job. Only Claude reads document bodies; this is the "carding boundary" Siddharth set on 6 Sep.

04Passages: the documents' own words

Cards say what a document is about. Sometimes a tool needs the exact words, for example SAM Live during a call. For that, every carded PDF, PowerPoint and Word file is also split into passages, one page, slide or section at a time. Today there are 12,728.

How passages are made and found.

How search works, exactly. SAM searches by words, not meaning. For documents (cards), it scores each one in memory: words that match, words in the title, all words matching, the document type asked for, freshness, and known names (products, regulations, regions, competitors). For passages, Postgres full-text search (English stemming, any word may match) finds candidates, then the same scoring re-ranks them. No embeddings anywhere. This was a deliberate choice (ROADMAP P5): add meaning-based search only once real questions show word search missing things.

Sources: prototype/build_passages.py; docs/supabase-sam-passages.sql (tsvector, plainto_tsquery with OR, ts_rank_cd); web/lib/passages.ts; web/lib/cards.ts searchAssets; docs/ROADMAP.md P5. Count read 26 Oct 2026.

05The rules that decide what can be answered

Not every file should answer a question. Five old versions of the same deck would bury the current one, and a 2019 brochure may describe a product that has changed. So SAM applies a few rules, the same in the app and in the database.

From files to answerable documents (counts from the 26 Oct health check).

1 · Version families: one answer slot per document

Every version, re-save and edition of a document ("v2", "Final", "(1)", a date prefix) is grouped into a family. Only the newest copy answers; the answer says "N older versions not shown". Editions such as "sharable", Japanese or Middle East are siblings: SAM picks the one the question needs (the sharable one when the rep is sending).

2 · Pre-2024 documents are excluded, with exceptions

A document answers only if it was published in 2024 or later (year from the document itself; if unknown, the year it was last modified). Exceptions: certificates, analyst reports, regulations, third-party research and brand assets (logos, signatures). Excluded documents never answer and are never offered as substitutes.

3 · Pins and overrides

An admin can pin an older document to keep it answering (Content tab, Pin / Unpin). A hand override can exclude a document (e.g. an empty deck) or split two files that were wrongly grouped. Cards marked low-confidence and "empty" are also out.

4 · Master lists (core.terms)

One shared list per tag: industries, asset types, products, competitors. Each has one label and its alternative spellings. The database rejects an industry or asset type that is not on the list, so "BFSI", "Banking" and "banking" can never become three industries. The same lists serve other Accops apps.

Sources: web/lib/family.ts; docs/supabase-sam-asset-families.sql; web/lib/cards.ts (eligibility, answerable); docs/brain/01-core-reference-lists.sql, 02-sam-wired-to-core.sql; docs/HANDOVER.md 30 Sep; docs/SALES-BRAIN-PLATFORM.md §1.

06Public or internal: what a rep may send

Every document is either public (published on accops.com, safe to send to a customer) or internal (Accops staff only). SAM decides this from the card and the link, never from the AI model's opinion, and says it on every answer.

The sendability line on every answer is written by SAM's code from this split. The model is never asked whether something can be sent.

The public wall is in the database

A database view, sam_v1_public_assets, holds only documents that are published on accops.com, current, eligible and not expired (22 on 26 Oct). A separate low-privilege database role, sam_web_reader, can read that view and nothing else; a test script proves 15 other objects are refused. Anything customer-facing (the future website bot) will use only this role.

Customer names stay inside

A card stores a real customer name separately from its anonymised description ("India's largest private bank"). The real name is in no view and no API response.

Passage policy (17 Oct 2026)

Siddharth decided that passage text of both public and internal documents may be stored in the database. Internal passages go only to tools holding a special permission (today: SAM Live). Everyone else gets public passages. One setting switches internal passages off instantly. SAM still never sends a file to anyone.

Sources: web/lib/cards.ts (assetLink, internalLink); web/lib/agent.ts (sendLine, guardSending); docs/supabase-sam-publish-requests.sql; docs/supabase-sam-v1-brain.sql; docs/supabase-sam-v1-public-proof.sql; docs/HANDOVER.md "Passages, 17 October 2026"; web/lib/passages.ts.

07Answering a question

All channels share one answer engine. The order matters: SAM searches the rep's own words first, so the model can only add to what plain search finds, never replace it. The model then picks the best documents by number. SAM's code, not the model, writes every document line from the card, so a document title can never be invented.

One engine behind every channel. The model chooses; the code writes.

Guards worth knowing

  • No invented documents. The model only returns numbers; titles, years and links come from cards.
  • Sending asks get a public document first when one fits; an internal one recommended for sending gets "Internal only".
  • Pricing is answered only from a current price list.
  • Honest gaps: when nothing fits, SAM says so, offers the nearest substitutes, and offers "Ask marketing to create this".
  • Last measured (1 Oct 2026): 27 of 28 test questions had the right document in the top 3; 0 invented document names. 20 of the 30 test questions are still modelled, not real.

08Feedback and day-to-day operations

SAM runs a daily loop with no one pressing buttons, and reports on itself every morning. Reps' ratings feed straight back into ranking and into marketing's to-do list.

What each rating button does.

/admin dashboard

Tabs for Overview, Usage, Quality (what reps told us, demotions), Content (cards, versions, exclusions, pins), Requests, System (scheduled jobs, model tokens) and Conversations. Test traffic is kept out of the numbers.

Morning digest, 08:30 IST

An e-mail to Siddharth: new content requests, things asked for but never requested, library changes, overnight carding, usage, and a "needs a look" list (a job that has not run in 30 hours, a silent change flow, model failures, the WhatsApp token running out).

Job log

Every scheduled job writes a row to sam_ops_runs: snapshot, carding prep, carding, health check, rollup and digest. "Nothing to do" and "did not run" are told apart.

Glossary

RAG
Retrieval-augmented generation: find the material first, then let the model answer only from it.
Card
SAM's structured one-page summary of one document. What the answer model reads.
Passage
A chunk of a document's own text, one page, slide or section, used to quote it.
Embedding
Numbers that capture meaning, used for meaning-based search. Not used by SAM today.
Registry
SAM's list of every file in Sales Collateral: name, folder, link, dates. No contents.
Carding
Reading a document once and writing its card. Done by Claude, nightly.
Family
All versions, re-saves and editions of one document. Only the newest answers.
Answerable
Current in its family and eligible (2024 or later, an exception, or pinned).
Pin
An admin's choice to keep an older document answering.
Grounding guard
The rule that SAM's code, not the model, writes every document line from the card.
Sendability line
The sentence on every answer saying what may go to a customer.
Public view / role
A database window showing only published documents, and a login that can see only that window.
Power Automate
Microsoft's workflow tool; it tells SAM when files change.
Supabase
The hosted Postgres database SAM keeps its data in.
MCP
Model Context Protocol: a standard way for AI tools to call SAM.
Webhook
A web address a system calls to say "something happened".
